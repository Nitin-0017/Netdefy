# NETDEFY Dataset Strategy: CICIDS2017 Benchmark & Forensic Plan

## 1. Overview and Verified Dataset Facts

The initial benchmark candidate selected for NETDEFY is the **CICIDS2017** dataset, generated by the Canadian Institute for Cybersecurity (CIC) at the University of New Brunswick (UNB).

- **Official Dataset Resource:** [UNB CICIDS2017 Repository](https://www.unb.ca/cic/datasets/ids-2017.html)
- **Official Registration Portal:** [http://cicresearch.ca/CICDataset/CIC-IDS-2017/](http://cicresearch.ca/CICDataset/CIC-IDS-2017/)
- **Archive Format:** `MachineLearningCSV.zip` (~225 MB compressed, ~2.8 GB uncompressed)
- **Component Files:** 8 distinct bidirectional network flow CSV files extracted via CICFlowMeter across five recording days (July 3, 2017 to July 7, 2017):
  1. `Monday-WorkingHours.pcap_ISCX.csv` (Baseline Benign)
  2. `Tuesday-WorkingHours.pcap_ISCX.csv` (Benign + SSH-Patator, FTP-Patator)
  3. `Wednesday-workingHours.pcap_ISCX.csv` (Benign + DoS Slowloris, Slowhttptest, Hulk, GoldenEye, Heartbleed)
  4. `Thursday-WorkingHours-Morning-WebAttacks.pcap_ISCX.csv` (Benign + Brute Force, XSS, SQL Injection)
  5. `Thursday-WorkingHours-Afternoon-Infilteration.pcap_ISCX.csv` (Benign + Infiltration)
  6. `Friday-WorkingHours-Morning.pcap_ISCX.csv` (Benign + Botnet ARES)
  7. `Friday-WorkingHours-Afternoon-PortScan.pcap_ISCX.csv` (Benign + PortScan)
  8. `Friday-WorkingHours-Afternoon-DDos.pcap_ISCX.csv` (Benign + DDoS)

## 2. Access Controls & Acquisition Protocol

During Phase 2 forensic discovery, the direct server endpoints (`https://cicresearch.ca/CICDataset/CIC-IDS-2017/browse.php`) were verified to enforce session authentication, returning **`HTTP 403 Forbidden`** when requested without valid user session tokens.

### Acquisition Policy:
- NETDEFY strictly adheres to institutional access controls and does not attempt to bypass web forms or scrape behind protected endpoints.
- The user completes the 1-minute registration form at `http://cicresearch.ca/CICDataset/CIC-IDS-2017/` to download `MachineLearningCSV.zip`.
- The acquisition utility (`scripts/acquire_dataset.py`) verifies the archive with SHA-256 cryptographic hashing and safely extracts it using Zip Slip protection into `data/raw/`.
- File integrity is tracked in `data/raw/manifest.json`.

## 3. Observed Anomalies in the Raw Telemetry

Forensic inspection of the official CICIDS2017 CSV files revealed several structural and statistical anomalies:

1. **Header Whitespace Inconsistencies:**
   - Raw column names contain irregular leading and trailing whitespace (e.g., `" Destination Port"`, `" Flow Duration"`, `" Label"`).
   - *Mitigation:* The inspection engine strips whitespace from all headers to produce canonical feature names while logging raw variations.
2. **Infinite Values (`+inf`, `-inf`):**
   - Columns calculating transfer rates (`Flow Bytes/s` and `Flow Packets/s`) divide by `Flow Duration`. When flow duration is zero, floating-point division produces positive and negative infinities.
   - *Mitigation:* Converted to `NaN` and imputed using training-partition medians.
3. **Exact Row Duplicates:**
   - A significant percentage of flow records are exact bitwise duplicates due to SPAN port capture taps monitoring both ingress and egress interfaces simultaneously.
   - *Mitigation:* Tracked via 64-bit row hashing during inspection; deduplicated downstream during preprocessing.
4. **Duplicate Column Headers:**
   - Redundant column headers (such as `Fwd Header Length` appearing in two positions) exist in some raw CSV releases.
   - *Mitigation:* Canonical schema mapping discards duplicate headers.

## 4. Potential Data Leakage Risks & Feature Treatment

To guarantee our models learn actual communication behavior rather than testbed simulation shortcuts, we categorize features into three risk tiers:

| Feature Category | Features | Leakage Risk & Forensic Recommendation |
| :--- | :--- | :--- |
| **Definite Leakage (Exclude)** | `Flow ID`, `Source IP`, `Destination IP`, `Timestamp` | **High Risk:** The attack infrastructure used static IP addresses. Algorithms readily memorize attack IP addresses and timestamps, achieving near 100% test accuracy on testbeds while failing in the real world. Must be dropped. |
| **Partial Leakage (Evaluate)** | `Source Port`, `Destination Port` | **Medium Risk:** Ephemeral source ports cause overfitting. Destination ports indicate target services (e.g. port 80/443 for web, 21 for FTP, 22 for SSH). We evaluate clustering into broad service categories (e.g., Well-Known <1024 vs Ephemeral >1024) rather than treating them as arbitrary continuous integers. |
| **Post-Event Leakage (Exclude)** | `Label` | **Critical Risk:** Must never be included as an input feature during training or threshold calibration. |
| **Statistical Flow Features (Retain)** | Duration, Packet lengths, Inter-arrival times (IAT), TCP Flags, Window sizes, Packet rates | **Safe:** Reflect dynamic transport and application layer traffic behavior. |

## 5. Recommended Evidence-Based Temporal Partition

Our central research question requires chronological evaluation:

```
+-----------------------------------------------------------------------------------------+
|                                    CICIDS2017 TIMELINE                                  |
+-----------------------------------------------------------------------------------------+
| Monday (Jul 3)   | Tuesday (Jul 4)  | Wednesday (Jul 5) | Thursday (Jul 6) | Friday (Jul 7) |
| Benign Only      | Brute Force      | DoS / DDoS        | Web Attacks      | Botnet, Port   |
+------------------+------------------+-------------------+------------------+----------------+
        \                 /                    |                    \                /
         \               /                     |                     \              /
   [ Phase 3 Training Partition ]     [ Validation Partition ]      [ Final Test Partition ]
   - Mon Benign + Tue Benign          - Tue Attacks + Wed           - Thu & Fri (All traffic)
   - Learn normal baseline manifold   - Calibrate threshold (tau)   - Untouched until final eval
```

### Partitioning Guardrails:
1. **Benign-Only Training Baseline:** The Autoencoder is trained strictly on normal benign flows from Monday and Tuesday morning.
2. **Threshold Calibration on Validation Set:** The reconstruction anomaly threshold $\tau$ (e.g., 99th or 99.5th percentile) is fitted on the validation partition and permanently frozen.
3. **Zero Test-Set Peeking:** Thursday and Friday partitions are held completely untouched until final benchmark evaluation.

## 6. Dataset Limitations & Unresolved Questions

1. **Synthetic Testbed Bias:** Generated in a controlled testbed environment over 5 days; real-world enterprise traffic exhibits significantly greater seasonal drift and noise.
2. **Rare Attack Support:** Attacks like Heartbleed contain fewer than 20 flow samples across the entire week, preventing statistical significance for that specific sub-category.
3. **Timestamp Standardization:** Date strings reflect Canadian local time (EDT) and vary in format between files (`yyyy-MM-dd` vs `dd/MM/yyyy`). The forensic inspection engine standardizes parsing using flexible format detection.
